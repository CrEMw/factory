## Layout

- `services/hub`: the hub service (Rust).
- `hub-web`: the web UI and MCP endpoint (SvelteKit).
- `apphost/apphost.mts`: the Aspire AppHost (TypeScript); local run and source of the Helm chart.
- `deploy/overlay`: Helm patches and `values.yaml` with neutral defaults, merged into the generated chart.
- `deploy/chart`: the Helm chart, generated by `tools/chart.sh`. Do not edit it by hand.
- `examples/seed`: a neutral seed directory for `HUB_SEED_DIR`.
- `tools`: the check script and tests.

## Running the checks

All checks run through one script:

```sh
tools/check.sh              # the parts your branch touches (diff against origin/main, plus uncommitted and new files)
tools/check.sh --all        # every part
tools/check.sh rust web     # only the named parts, with full output, stopping at the first error
```

Without arguments the script needs `origin/main` (`git fetch origin`). It prints one line per part and, on error,
the tail of that part's log.

The `dagger` check of a pull request runs the same parts in the tools image, so it needs only Dagger and a container
engine on your machine:

```sh
dagger call check --source=.
```

The `leak` check and the release are described in [docs/releasing.md](docs/releasing.md).

If mise is installed, the script installs and uses the pinned tool versions
(Rust from `services/rust-toolchain.toml`, Node, pnpm, Helm, yq, kubectl). Without mise the tools are taken from
`PATH`.

Parts:

| Part         | What it runs |
|--------------|--------------|
| `rust`       | `cargo test --locked` in `services` |
| `rust-lint`  | `cargo fmt --check` and `cargo clippy --all-targets --locked -- -D warnings` |
| `web`        | in `hub-web`: `pnpm install --frozen-lockfile`, `pnpm run build`, `pnpm run check`, `pnpm run test` |
| `node-tests` | `npm ci --prefix .tools`, then `node --test` over `tools/test-*.mjs` and `tools/gate-layout.test.mjs` |
| `chart`      | AppHost restore, `tools/chart.sh`, and a check that `deploy/chart` does not drift from AppHost and overlay |
| `pg-schema`  | the baseline schema against the migration chain (see `docs/migrations.md`); a no-op without `services/hub/baseline` |
| `cyrillic`   | `tools/no-cyrillic.sh` over the source directories (only the Russian i18n file may contain Cyrillic) |
| `apphost`    | eslint and `tsc --noEmit` for `apphost.mts` (local only) |
| `helm-lint`  | `helm lint` of the chart with fake image digests (local only) |
| `graph-pg`   | `tools/test-graph-pg.sh`: graph and routes on a real Postgres in Docker (local only) |

`graph-pg` and the catalog comparison in `pg-schema` need a running Docker.

If you change `apphost/` or `deploy/overlay/`, run `tools/chart.sh` and commit the regenerated `deploy/chart`
together with your change.

## Branches and pull requests

- Work on a branch named `f/<short-english-slug>`, for example `f/ticket-filter`. Do not push to `main`.
- Write everything in English: branch names, commit messages, PR titles and descriptions, code comments and docs.
- Use a Conventional Commits title, for example `feat(hub): add ticket filter` or `fix(hub-web): keep locale on login`.
  Common scopes: `hub`, `hub-web`, `chart`, `apphost`, `tools`, `docs`.
- Keep a PR to one change. Say in the description what changed, why, and how you checked it.
- Run `tools/check.sh` before opening the PR and make sure every part it picks is green.
- Add an entry under "Unreleased" in `CHANGELOG.md` for user-visible changes.
- Do not commit secrets, real hostnames, or personal data. Use neutral examples such as `hub.example.com`,
  account `acme`, people `alice` and `bob`.

## Reporting security issues

Do not open a public issue for a vulnerability. See `SECURITY.md`.
